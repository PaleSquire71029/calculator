# 知行 AI 数据安全与隐私说明

最后更新：2026-10-18

本文说明知行 AI 学习版、AI 代理 Worker 与模型服务商之间的数据流。它不是“零数据出境”或“模型供应商绝不留存数据”的承诺；实际留存和训练政策还取决于你在管理中心配置的第三方 API 服务商。

## 1. 数据流与处理边界

1. 用户在网页输入的问题、对话上下文，以及主动附加的图片/文件内容，会由浏览器发送到知行 AI Worker。
2. Worker 读取当前模型配置和提示词，将必要的消息转发到管理员配置的模型 API。使用图片时，图片数据也可能被发送给模型服务商。
3. Worker 将模型响应返回浏览器。当前请求处理逻辑不会主动把用户问题正文、回答正文或图片写入 Durable Object 的调用统计。
4. Durable Object 用于保存管理配置和有限的调用元数据；管理配置可能包含管理员自定义的模型 API Key。请将 Cloudflare 账户、Worker 与 Durable Object 的访问权限视为敏感权限。
5. 浏览器、网络服务、Cloudflare 平台和模型服务商可能依其各自的政策处理技术日志、请求元数据或内容。知行项目无法仅凭 Worker 代码保证这些外部系统不留存数据。

## 2. 当前记录与不记录的内容

### 当前调用统计记录

- 请求时间、题型/场景、成功或失败、HTTP 状态码、模型 ID。
- 供应商返回的 Token 用量（如果供应商提供）。
- 最近 20 条调用元数据。

### 当前代码不主动持久化

- 用户问题正文与 AI 回答正文。
- 上传图片的原始内容。
- 完整的对话消息列表。

注意：不写入项目自己的调用统计，不等于数据从未经过第三方服务，也不代表 Cloudflare、浏览器扩展、设备备份或模型供应商的日志政策不适用。不要提交密码、API Key、身份证件、私人照片、学校/家庭隐私或其他不必要的敏感内容。

## 3. 管理员必须执行的保护措施

- 将 `ADMIN_PASSWORD`、`ADMIN_SESSION_SECRET`、`AI_API_KEY` 设为 Cloudflare Worker Secrets；绝不要写入 GitHub 文件、前端 JavaScript、截图、Issue 或导出的配置文件。
- 设置唯一且高强度的管理密码（建议至少 16 位随机字符），不要与 GitHub、邮箱或其他网站共用。
- 为 `ADMIN_SESSION_SECRET` 单独生成高熵随机值。若该值曾泄露，立即轮换；轮换后旧签名会话应失效。
- 限制 GitHub 仓库和 Cloudflare 账户的协作者与权限；开启 GitHub 双重验证，并定期检查提交历史、Actions 日志和部署配置中是否意外出现密钥。
- 模型 API 根地址只使用可信服务商的 HTTPS 地址；核对域名、模型权限、计费限额和数据处理政策。不要使用不明代理或来历不明的免费 API。
- 如果 API Key 曾被提交到仓库、发到聊天或出现在日志/截图中，立即在服务商控制台撤销并重新生成；仅删除文件不代表旧密钥已从 Git 历史中消失。
- 管理员退出管理页面并避免在共享设备上保存密码。不要将管理会话令牌复制给他人。

## 4. 已有保护与限制

当前 Worker 代码已实现以下保护：

- 管理接口使用 HMAC 签名的限时 Bearer 会话，API Key 不通过管理 API 返回；导出配置不包含密钥。
- 自定义模型 API Key 使用 AES-GCM 加密后存入 Durable Object。优先使用独立 Secret `ADMIN_ENCRYPTION_KEY`；为兼容旧部署，会依次尝试 `ADMIN_SESSION_SECRET`、`ADMIN_PASSWORD`。检测到旧版明文 Key 时会在读取配置时自动加密；若加密密钥已更换但旧密钥仍保留在可用 Secrets 中，也会尝试迁移到当前首选密钥。
- 登录、健康检查、AI 调用，以及管理页模型列表/连接测试有基于 Durable Object 的持久化 IP 限流；限流存储不可用或未绑定 `ADMIN_STORE` 时会拒绝请求，不再静默退回进程内计数。
- 请求 JSON 使用流式读取并设置体积上限；上游非流式响应、模型列表/连接测试响应均有大小限制，流式输出限制为 4 MB，超限会终止读取并向前端发出错误事件。上游请求禁止自动跟随重定向，以免密钥随请求转发到意外地址。
- 上游地址只接受 HTTPS、公开域名、不接受账号密码、IP 字面地址（包括常见缩写数字主机）或自定义端口，并拦截常见本机/内网域名后缀；请求有超时限制。地址校验不能保证外部域名的 DNS 始终指向安全的公网地址。

这些保护不能代替完整的安全审计。特别是：

- 浏览器的 CORS/Origin 检查不是身份认证机制；非浏览器客户端可以伪造请求头。公开 AI 接口仍可能被分布式来源或可轮换 IP 的请求滥用。
- 必须在 Cloudflare Worker Secrets 中配置独立、高熵的 `ADMIN_ENCRYPTION_KEY` 与 `ADMIN_SESSION_SECRET`，避免把 API Key 加密绑定到管理密码。密钥轮换前应保留旧加密候选，触发配置读取并确认 Key 已重新加密，然后再移除旧密钥；如果所有匹配旧密文的密钥都丢失，需重新输入 API Key。
- 限流不能完全阻止代理网络、分布式 IP 或应用层的拒绝服务。可结合 Cloudflare WAF/速率规则与服务商账单限额。
- 如果某个 API 域名被错误配置、遭 DNS 劫持或解析到非预期目标，仅靠域名后缀和 HTTPS 校验无法完全排除风险；只配置可信服务商，并禁止不必要的自定义代理地址。
- AI 可能输出错误内容；不要将其输出当作安全审查、法律、医疗或其他高风险决策的唯一依据。

## 5. 发生疑似泄露时

1. 立即撤销并轮换可能泄露的模型 API Key。
2. 更改 `ADMIN_PASSWORD` 与 `ADMIN_SESSION_SECRET`，重新部署 Worker，并确认旧管理会话失效。
3. 检查 Cloudflare Worker 日志、GitHub 提交记录和 Actions 日志；避免在报告中再次粘贴密钥或用户内容。
4. 评估受影响的数据、服务商及用户，并按适用的服务条款和法律要求处理通知义务。
5. 清理公开文件并不等于清除所有 Git 历史、缓存或第三方副本；应按相应平台的流程处理。

## 6. 用户使用建议

只上传完成学习任务所必需的题目部分；先裁掉姓名、学号、学校班级、通知栏、定位信息和其他无关个人信息。使用图片或文档前，确认自己有权分享其中的内容。若不希望内容发送给当前配置的模型服务商，请不要提交该内容。
